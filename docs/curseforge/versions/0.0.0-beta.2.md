<h2>v0.0.0-beta.2 - Mod-loading crash fix</h2>

<p>Hotfix for a mod-loading crash introduced with the configurable log filter in beta.1.</p>

<h3>Fixed</h3>
<ul>
<li><strong>Mod-loading crash from the benign-log filter</strong>: the filter is installed from the <code>@Mod</code> constructor, which runs before NeoForge loads this mod's COMMON config. Any log line emitted in that window &mdash; for example Supplementaries' <code>DepthDataHandler</code> static initializer triggering a Netty debug log &mdash; reached the config value before it was loaded and threw <code>IllegalStateException: Cannot get config value before config is loaded</code>. That escaped as an <code>ExceptionInInitializerError</code> and aborted loading, with the crash report blaming whichever mod happened to log first (<code>supplementaries</code>). The config accessors now fall back to the built-in defaults until the spec is loaded, so early stale-NBT noise is still suppressed and no crash occurs.</li>
</ul>

<blockquote>
All patches are no-ops when the mod they target is absent. Nothing is bundled and nothing is a hard dependency.
</blockquote>
