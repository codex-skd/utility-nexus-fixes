<h2>v1.1.1 - BvaMixinPlugin crash noise fix</h2>

<p>Small bug-fix release. No new features.</p>

<h3>Fixed</h3>
<ul>
<li><strong>Startup log noise from <code>BvaMixinPlugin</code></strong>: the mixin config plugin that
gates the two optional Better Villager Animations soft mixins called
<code>ModList.get().isLoaded(...)</code> to check whether that mod was present. Mixin config plugins
are queried while Mixin prepares its configs, a phase that runs <em>before</em> FML has finished
populating <code>ModList</code> — so <code>ModList.get()</code> returned <code>null</code> and every
single launch logged two <code>NullPointerException</code>s wrapped in
<code>InvalidMixinException</code>, even though nothing actually broke (the two soft mixins were
correctly skipped either way, since <code>bettervillageranimations</code> isn't loaded in that
window). The plugin now guards against <code>ModList.get()</code> returning <code>null</code> and
treats it the same as "mod not loaded", so the log stays clean.</li>
</ul>
