<h2>v1.2.0 - Better Party member-health crash guard</h2>

<p>Adds a new optional, server-side compatibility patch for <strong>Better Party</strong>. Same
compatibility-patch philosophy as the rest of this mod: it never touches the affected mod's jar,
and the patch only activates when that mod is present.</p>

<h3>Added</h3>
<ul>
<li><strong>Better Party member-health crash guard</strong>: <code>BetterPartyServerApi.memberHealth(ServerPlayer)</code>
falls back to <code>new PartyMemberHealth(player.getHealth(), player.getMaxHealth())</code> whenever
no custom health-provider add-on is registered. That record's constructor throws an
<strong>uncaught</strong> <code>IllegalArgumentException</code> if either value is non-finite or
<code>maxHealth &lt;= 0</code>, which propagates out of <code>BetterParty#onServerTick</code> and
crashes the <strong>entire dedicated server</strong> mid-tick &mdash; for every player online &mdash;
the instant a single player's <code>generic.max_health</code> attribute gets corrupted, even
momentarily. New soft, server-only mixin <code>BetterPartyMemberHealthGuardMixin</code> (gated by
<code>BvaMixinPlugin</code> on <code>better_party</code> actually being loaded) wraps the two
vanilla <code>ServerPlayer</code> accessor calls that feed the record and substitutes a safe finite
value if either reading is currently invalid, logging a warning instead of crashing.</li>
</ul>

<h3>Notes</h3>
<blockquote>This patch stops the crash, it does not fix whatever corrupts the player's
<code>generic.max_health</code> attribute in the first place &mdash; if it keeps happening, look at
what other mod/enchantment is stacking attribute modifiers on that player around the same time.
Optional dependency on <code>better_party</code> (server side). No new compile-time dependency was
added to build this mod: the target class is referenced by name only (<code>@Pseudo</code> soft
mixin target), never on the compile classpath. Verified: <code>./gradlew clean build</code> is
green.</blockquote>
